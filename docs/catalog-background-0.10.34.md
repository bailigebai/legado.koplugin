# v0.10.34 后台目录补全

用户已更新 v0.10.33，确认跨章翻页恢复正常，但《朕真的不务正业》在正文阅读期间目录仍没有自动补全。此次目标是不打开侧栏、不手动翻目录页，也能持续收集完整目录。

## 已复现的问题和修改

- 普通规则输出上限 1,000 条同时约束目录：1,407 条的单页目录会直接失败。增加仅用于目录选择的解析入口，最多 10,000 条；不修改共享规则引擎实例或全局常量，搜索、单章提取和其他普通规则仍维持 1,000 条限制。HTML 节点数、字节、递归等保护保留。
- 后台扫描原先等待 6 秒启动，快速连续跨章还会重新计时。改为首屏提交后让出 100ms 给界面，然后开始完整扫描；已有任务或定时器继续复用，目录收集不受界面刷新节流约束。
- 后续目录网页临时超时会使整个扫描停止。阅读会话的后台扫描现在从失败的 URL 重试，最多两次，分别等待 1 秒和 3 秒；保留已解析前缀，不从首页重新开始。永久解析/存储错误、HTTP 404、拒绝访问等不自动重试。退出或休眠取消任务和重试。
- 原生阅读器跨章关闭旧文档时会取消扫描。相同书籍/站点的章节替换保留扫描；新章等待打开期间若目录完成，提交时继承最新列表和完成标记，避免旧快照覆盖新结果。
- 阅读后台的网站目录页上限由 64 放宽到 512，总条目仍限制为 100,000；防循环与去重保留。换源比较等普通目录请求继续使用原 64 页限制。
- 最终失败记录诊断，独立阅读的进度文字在重画时显示“目录加载失败”，不再误显示永久加载中；打开目录可继续使用已有条目并重试缺失页。

这些都是代码与受控网络测试确认的失败路径，尚不能确认其中哪个是用户当前站点的实际原因。没有调整已经恢复正常的跨章画面提交、章内动画或授权。

## 验证及边界

新测试经过真实 RuleEngine、BookService、ReaderSession 的阅读启动入口，不打开侧栏、不发送翻页事件，分别验证 JSON、默认 HTML、CSS、XPath 形式的 1,407 条目录，以及 80 个网站页面共 1,600 条目录。核对末条标题、完整保存、普通规则限制保持、网络重试不重复前缀、同书跨章继续、候选章节延后就绪、错误可见以及暂停/退出取消。

2026-09-26：后台补全专项 133 条断言、既有目录分页专项 42 条断言通过；全量 152 组 Lua 测试、47,014 条断言通过；KOReader v2026.07.1 兼容 12 组、37,882 条断言通过。命名空间、官方 SQLite、文档输出及安装包安全/可重复构建检查通过，原 208 条网页存档和导入书源规则回放保持通过。

本轮还实际下载了 [258 文学网的该书目录](https://www.258wx.net/10/10105/)，网页存在当前 HTML 解析器不接受的 `mismatched closing tag div`，该站的真实网页验证未通过。此站是排查时找到的公开样本，用户未提供正在使用的站点，不能将它当成用户书源，也没有为了通过测试修改网页。该类 HTML 容错兼容仍未解决；当前修改不能保证任意失效或不兼容书源都能完成目录。

未检测到连接的 Kindle，本轮没有读取设备日志，也没有完成实机速度验收。临时公开网页和书源样本不进入安装包。

## 验收

1. 安装 v0.10.34，完全退出并重启 KOReader。现有书源、书架、进度和授权保留，不需要重新激活。
2. 打开原来那本书，停留正文正常阅读，无需打开目录。稍后打开目录，应能看到后台补齐的章节和最终页数。
3. 自动补全期间跨到下一章再打开目录，应继续使用已加载结果，不回退到前 15 章。
4. 如果进度处显示“目录加载失败”或仍未补齐，请保留同次 `koreader/crash.log`，并提供该书当前站点名，以便核对具体网页和规则。站点网络耗时仍存在，不能保证所有站点固定秒数内完成。
