# v0.10.10 后三章预读与无感跨章优化

按批准的 B 方案实施。本版以无感阅读的窗口复用为主要优化；原生 KOReader 仍需打开下一章节文档，不把两种模式的速度混为一谈。授权入口、既有密钥、919 个默认书源和阅读数据规则沿用 v0.10.9。

## 已查明的问题与修改

- 原来只有一个正文预取任务：下一章慢会拖住后两章。现在最多两路请求，优先下一章，补齐 N+1、N+2、N+3；同章前台读取加入已有任务，跨章保留有用任务并补新的一章。正文的全部网页分页完成、清洗及写盘成功后才计为已缓存。
- 初始目录只有三章时，原来第 4 章要等六秒补目录。现在目录不足后三章范围就立即补齐；六秒界面刷新节流不用于拖延正文准备。
- 无感阅读原来每章新建窗口，入场动画又构造一遍首屏控件。现在准备候选正文并验证，进度保存和会话提交成功后替换活动窗口内的章节；复用背景、事件绑定、时钟和已准备分页索引。失败保留旧正文，旧章节代理不能操作新章节。外部完成回调延迟到窗口交接后，防止同步关闭/再导航破坏临时候选；原生排队候选在执行 doShowReader 前检查是否被取消，避免取消后再创建引擎。KOReader 的更早 ShowingReader 广播可能已关闭旧章，不能据此承诺原生旧引擎始终保留。
- 后台分页按页分时执行，在可释放临时绘制资源的边界检查约 8 ms 软预算；超时保留计算位置，不发布半页索引。长段落保留 UTF-8 窗口起点，避免每页重复从段首扫描；极窄排版容不下缩进时减去缩进，保证正文推进。预算是调度目标，不是所有设备单次调用的硬上限。
- 除当前活动正文，后台最多保留三个准备模型、8 MiB 原始正文与 10000 个页起点。超限淘汰远章排版，已写盘正文仍可读；这些数值不是 Lua 总内存占用上限。
- 新安装默认使用普通翻页跨章，不再默认额外执行分段净屏；已保存的用户动画选项保留。未移除 Kindle 驱动必要的刷新同步。
- 增加按次序号关联的缓存、进度保存、前台等待、窗口/排版复用、buffer 绘制和动画提交计时。日志仅记录阶段、时间、模式与数值，不记录正文、书源凭据或密钥。buffer 绘制完成不等于墨水屏已经显示完成。

## 安装与验收

1. 完全退出 KOReader，解压 `legado.koplugin-v0.10.10-20260916.zip`，将 `legado.koplugin` 覆盖到 `koreader/plugins/`；保留书架、设置、授权及缓存数据。
2. 确认版本为 **0.10.10**。从阅读顶栏启用“无感阅读”，确认预取章节为 **3**。预取值为 0 时仍关闭自动预取；不会擅自改掉已有设置。
3. 首次验证可把跨章净屏关闭、翻页动画关闭，以观察软件等待；之后再开启喜欢的动画对照。已有动画设置不会被升级自动清除。
4. 正常阅读一章，让后三章完成下载，再断网连续跨三章；内容应该完整且无需网络。网络尚未返回或站点解析失败时，不能保证未获得的正文立刻出现。
5. 前后快速切章、开目录/设置再返回、休眠恢复；检查当前位置、字体边距、章节名称和背景连续，不能掉到缓存目录。
6. 若仍有 3–4 秒停顿，在 KOReader 开启调试日志，分别测普通翻页与跨章，保留该轮 `koreader/crash.log` 的 `[LegadoTiming]` 行及当前阅读模式。不要只用“reader_ready”一项判断耗时；查看同 attempt 的累计时间和 paint_drawn/animation_submit。

## 验证记录

最终冻结代码复验（2026-09-16）：

- 全量 Lua：132 组、44,790 断言、0 失败；命名空间、真实 HTML 写入、EPUB、发布白名单、恶意 ZIP、版本匹配及可重现构建检查通过。
- KOReader v2026.07.1 宿主兼容：32 个 UI 模块，原生界面 12 组、37,875 断言通过；官方 SQLite 路径通过。日志中的“缺少 legado.missing”是预期故障注入。
- 最终压力：500 次跨章（含 100 次真实 App 目录入口）、200 次菜单返回、50 次模式切换、50 次休眠恢复，1,721 断言通过。关闭后没有残留任务或插件窗口。Lua heap 在第100/200/300/400/500次分别为2140.61/2168.04/2217.46/2225.74/2216.59 KiB，未观察到持续线性增长。该压力计时包含测试中排空后台分页，不作为输入到显示耗时。
- 两个独立上下文分别审查 Session 与阅读器/分页/原生接线；发现的暂停、晚到回调、改选章节、候选取消、重排失败指纹及长段扫描问题均加反例并修复复验。最终无未解决的 Critical/Important 运行代码问题；原生上游行为与实机限制单列。
- 40 次宿主缓存对照：旧版窗口复用0/40，新版40/40，关闭均为0任务。动画关闭、内存存储、模拟字体/屏幕条件下，两版跨章CPU P95均约1 ms、普通翻页约2 ms，精度不足以证明设备提速；有意义的结论是重复窗口路径已消除，不能将这些数字宣传为Kindle速度。

最终日志：`.tools/verification-0110-full.log`、`verification-0110-native.log`、`verification-0110-soak.log`；对照记录 `.tools/chapter-latency-0110-host.json`。

真实站点抽测：英文小说网（17）查询“加”，搜索/详情/前四章目录/正文/HTML通过；森林文学（84）查询“阳神”，首次正文请求10秒超时，单独以20秒超时重试后全链路通过。最初对17查询“阳神”无搜索结果，未把它记为解析成功。抽样正文分别1779/9814字节，校验缓存checksum后交给生产独立控件，按测试字体完整前后读取6/11页，无异步错误或关闭后任务。平台字体与屏幕仍是宿主替身，网页正文不随包分发。这不是919个站点全部可用的承诺。

可重复宿主对比：

```powershell
.tools/python/python.exe scripts/benchmark_chapter_transition.py --baseline dist/legado.koplugin-v0.10.9-20260916.zip --output .tools/chapter-latency-0110-host.json
```

此对比使用真实 Session/Reader 控制代码，但字体、屏幕及存储为替身，动画关闭。它验证窗口复用和代码路径，不能模拟 Kindle 的 CPU、持久化和墨水屏时间。

## 仍待实机验证

本次电脑未检测到 Kindle。当前证据可确认串行阻塞、六秒目录等待和重复窗口构造已在代码层处理；无法给用户此前的 3–4 秒拆出真实设备占比，也不能承诺物理“零延迟”。无感热准备跨章的设备目标仍是软件 P95 ≤200 ms、相对普通翻页额外 ≤100 ms，需同设备各 30 次以上验证；屏幕完成显示另测。原生模式逐章重新开引擎及上游 ShowingReader 提前关闭旧章的行为仍存在；本轮没有覆盖完整原生休眠后的旧引擎恢复验收。原生无缝切章需要另行实施 C 方案。
