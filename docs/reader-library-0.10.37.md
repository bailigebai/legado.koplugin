# v0.10.37：统一书架与阅读功能

## 安装

从当前仓库的 `downloads/` 或开发交接目录取得 `legado.koplugin-v0.10.37-20260928.zip`；正式发布后也可从 GitHub Release 下载。解压后将其中唯一的 `legado.koplugin` 文件夹覆盖到 KOReader 的 `plugins` 目录，完全重启 KOReader。保留用户数据目录和原有设置文件；升级不需要重新激活。

## 使用与验收

1. 打开“工具 → 不亦阅乎”。书架最近读的一本在首页顶部，显示较大的封面和简介；下面是四本封面，下一页开始是 4 列 × 3 行。点击四组功能，子页面可返回原书架页。“阅读回顾”只在书架“更多”中出现；两种阅读模式的菜单保留当前书籍小票和阅读统计，不再重复放置全局回顾入口。
2. 打开“书源与下载 → 缓存书籍”，选择在线书源书籍；可直接缓存整本、导出 EPUB，或在“缓存部分章节”中跳到截至章，任务应从第 1 章缓存到该章。“下载管理 → 新建缓存任务”可重复同一流程，并显示任务范围与完成数。整本缓存完成才显示封面右下角“已下载”。断网可重新打开已缓存章节。
3. 打开“找书 → 微信读书”，微信扫码确认后同步书架；在“书城发现”打开飙升榜、热搜榜、新书榜、小说榜或总榜，应看到微信读书当前榜单书籍。榜单与关键词搜索都可连续翻页，超过首批 20 本时应自动加载下一批，断网失败后可再次点“下一页”。打开一本未收藏的书并点“加入微信书架”，返回后应能在微信书架找到它。点“开始阅读”，检查历史章节位置。打开“阅读评论”，点一条查看全文；点“下一页”才读取下一批，失败可在当前页重试，返回详情后不应被迟到结果拉回。正常取章优先直接请求正文；若正文接口返回空内容，才读取阅读页参数重试。会话失效时重新扫码。首次真实扫码、付费章节和长书正文需在 Kindle 上验收。
4. 打开“更多 → AI 服务”，分别选服务商，在 Kindle 上选一个密钥 JSON 文件，测试连接。原生阅读划词选“AI 解释”；独立阅读长按正文行。修改补充要求后应出现解释。实际 API 连接及费用取决于用户密钥和服务商状态，桌面测试没有发送真实请求。
5. 打开“更多 → 插件缓存”，核对总量和三类缓存。确认清理后，返回书架检查书、进度、授权与导出 EPUB 仍在；离线章节清除后“已下载”角标消失。当前阅读的书受保护，运行中的下载需要先取消或完成。

## 已验证与限制

桌面自动规格覆盖导航、扫码会话模拟、目录与正文分片、历史位置、书城、评论、AI 请求构造、两种阅读入口、缓存统计与清理、安装包清单。已直接核对微信读书公开榜单接口的首批和续页响应；微信读书真实账号、Kindle 触控及 AI 真实密钥仍需实机验证。微信读书榜单依赖其网页接口，服务端变动后可能需要更新；付费章节受账号权限限制；书源实际网页的目录和正文质量取决于导入规则与站点。项目现有 `discovery_rules_spec.lua` 需要未随仓库提供的 `sources/yuedu-260114.json`，缺失时该项不能执行。

取章方案比较：每章都取阅读页较慢且长书可能超过响应上限；只生成本地参数更快但服务端规则变化时缺少退路；本版采用本地参数优先、空回包时读取阅读页重试，正常路径少一次网页请求。桌面模拟验证了请求顺序与回退，实际微信服务和用户反馈的普通书源跨章卡顿仍需设备复验。

本次继续减少微信读书取章的本地处理：章节分片和阅读页的原始响应仅在出现服务端错误码字段时尝试 JSON 解析。桌面回归确认普通正文不再额外解析，登录失效仍可续期；这不能证明普通书源约每 20 章出现一次的偶发卡顿已解决。出现卡顿时保留同次 `crash.log` 中的 `[LegadoTiming]` 记录，便于区分网络、解析和排版耗时。

微信扫码轮询在等待与已扫码状态后会向微信传回 `last` 状态游标；换新二维码时清零。桌面模拟验证了状态转移，仍需真实微信账号在 Kindle 上确认二维码显示、手机扫码、登录与重启后会话恢复。

扫码二维码从取得微信标识起最多等待五分钟；到期会提示重新登录。普通长轮询超时继续等待，临时网络错误隔三秒重试，避免弱网下误报二维码过期或持续无上限轮询。该行为已用可控时间与失败回包验证，尚未在 Kindle 实际网络下测量。

电脑直连确认二维码票据和二维码标识两个公开接口均返回 HTTP 200 与预期字段；未保存票据或扫码标识。微信书架同步会结合 `recentBooks` 顺序、书籍行内进度与独立 `bookProgress` 列表，避免缺少独立进度列表时最近阅读大封面排错或进度显示为零。桌面规格已验证，真实账号书架仍需验收。

公开点评依据[微信读书官方字段说明](https://github.com/Tencent/WeChatReading/blob/main/skills/review.md)核对双层 `review`、内层 `book.bookId`、`reviewsHasMore`、末条 `idx` 与 `synckey`。桌面规格验证跨书过滤、按需续页、失败重试和离页取消；真实账号是否返回相同字段仍需设备验收。

本次完整 Lua 回归为 176 项通过、1 项因缺少外部 `sources/yuedu-260114.json` 样本失败，共 47,403 条断言；定向扫码规格 3 项、46 条断言通过。安装包清单与可重复构建检查、命名空间和敏感信息扫描通过。
