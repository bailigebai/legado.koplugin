# v0.10.37：统一书架与阅读功能

## 安装

从当前仓库的 `downloads/` 或开发交接目录取得 `legado.koplugin-v0.10.37-20260928.zip`；正式发布后也可从 GitHub Release 下载。解压后将其中唯一的 `legado.koplugin` 文件夹覆盖到 KOReader 的 `plugins` 目录，完全重启 KOReader。保留用户数据目录和原有设置文件；升级不需要重新激活。

## 使用与验收

1. 打开“工具 → 不亦阅乎”。书架最近读的一本在首页顶部，显示较大的封面和简介；下面是四本封面，下一页开始是 4 列 × 3 行。点击四组功能，子页面可返回原书架页。“阅读回顾”只在书架“更多”中出现；两种阅读模式的菜单保留当前书籍小票和阅读统计，不再重复放置全局回顾入口。
2. 打开“书源与下载 → 缓存书籍”，选择在线书源书籍；可直接缓存整本、导出 EPUB，或在“缓存部分章节”中跳到截至章，任务应从第 1 章缓存到该章。“下载管理 → 新建缓存任务”可重复同一流程，并显示任务范围与完成数。整本缓存完成才显示封面右下角“已下载”。断网可重新打开已缓存章节。
3. 打开“找书 → 微信读书”，微信扫码确认后同步书架；首页顶部点“继续阅读”应直接打开最近阅读的书，点封面仍可看详情。在“书城发现”打开飙升榜、热搜榜、新书榜、小说榜或总榜，应看到微信读书当前榜单书籍。榜单与关键词搜索都可连续翻页，超过首批 20 本时应自动加载下一批，断网失败后可再次点“下一页”。打开一本未收藏的书并点“加入微信书架”，返回后应能在微信书架找到它。点“开始阅读”，检查历史章节位置。打开“阅读评论”，点一条查看全文；点“下一页”才读取下一批，失败可在当前页重试，返回详情后不应被迟到结果拉回。正常取章优先直接请求正文；若正文接口返回空内容，才读取阅读页参数重试。会话失效时重新扫码。首次真实扫码、付费章节和长书正文需在 Kindle 上验收。
4. 打开“更多 → AI 服务”，分别选服务商，在 Kindle 上选一个密钥 JSON 文件，测试连接。原生阅读划词选“AI 解释”；独立阅读长按正文行。修改补充要求后应出现解释；如果设置无法保存，会提示“设置保存失败”，原设置保持不变。实际 API 连接及费用取决于用户密钥和服务商状态，桌面测试没有发送真实请求。
5. 打开“更多 → 插件缓存”，核对总量和三类缓存。确认清理后，返回书架检查书、进度、授权与导出 EPUB 仍在；离线章节清除后“已下载”角标消失。当前阅读的书受保护，运行中的下载需要先取消或完成。

## 已验证与限制

桌面自动规格覆盖导航、扫码会话模拟、目录与正文分片、历史位置、书城、评论、AI 请求构造、两种阅读入口、缓存统计与清理、安装包清单。已直接核对微信读书公开榜单接口的首批和续页响应；微信读书真实账号、Kindle 触控及 AI 真实密钥仍需实机验证。微信读书榜单依赖其网页接口，服务端变动后可能需要更新；付费章节受账号权限限制；书源实际网页的目录和正文质量取决于导入规则与站点。项目现有 `discovery_rules_spec.lua` 需要未随仓库提供的 `sources/yuedu-260114.json`，缺失时该项不能执行。

取章方案比较：每章都取阅读页较慢且长书可能超过响应上限；只生成本地参数更快但服务端规则变化时缺少退路；本版采用本地参数优先、空回包时读取阅读页重试，正常路径少一次网页请求。桌面模拟验证了请求顺序与回退，实际微信服务和用户反馈的普通书源跨章卡顿仍需设备复验。

本次继续减少微信读书取章的本地处理：章节分片和阅读页的原始响应仅在出现服务端错误码字段时尝试 JSON 解析。桌面回归确认普通正文不再额外解析，登录失效仍可续期；这不能证明普通书源约每 20 章出现一次的偶发卡顿已解决。出现卡顿时保留同次 `crash.log` 中的 `[LegadoTiming]` 记录，便于区分网络、解析和排版耗时。

微信扫码轮询在等待与已扫码状态后会向微信传回 `last` 状态游标；换新二维码时清零。桌面模拟验证了状态转移，仍需真实微信账号在 Kindle 上确认二维码显示、手机扫码、登录与重启后会话恢复。

微信登录二维码按设备 DPI 放大，并限制在屏幕短边的 80% 内。桌面规格验证了小屏约束、大屏缩放及离页关闭；实际手机扫码清晰度仍需 Kindle 验收。

扫码二维码从取得微信标识起最多等待五分钟；到期会提示重新登录。普通长轮询超时继续等待，临时网络错误隔三秒重试，避免弱网下误报二维码过期或持续无上限轮询。该行为已用可控时间与失败回包验证，尚未在 Kindle 实际网络下测量。

登录后的网页 Cookie 保留微信返回的访问令牌原文，不再把 `+`、`/`、`=` 改写为网址编码；异常控制字符和 Cookie 分隔符会在发请求前拒绝。桌面规格验证了这两种边界，真实账号 Cookie 仍需登录验收。

电脑直连确认二维码票据和二维码标识两个公开接口均返回 HTTP 200 与预期字段；未保存票据或扫码标识。微信书架同步会结合 `recentBooks` 顺序、书籍行内进度与独立 `bookProgress` 列表，避免缺少独立进度列表时最近阅读大封面排错或进度显示为零。桌面规格已验证，真实账号书架仍需验收。

公开点评依据[微信读书官方字段说明](https://github.com/Tencent/WeChatReading/blob/main/skills/review.md)核对双层 `review`、内层 `book.bookId`、`reviewsHasMore`、末条 `idx` 与 `synckey`。桌面规格验证跨书过滤、按需续页、失败重试和离页取消；真实账号是否返回相同字段仍需设备验收。

微信书城翻页遇到整批重复结果时，只要服务端游标仍向前且声明还有后续，页面会提示“本批没有新书，点击下一页继续”，保留下一页入口。桌面规格验证可用新游标继续取得后面的书；真实榜单仍需账号实测。

下载管理原本在初次打开且没有活跃任务时不会安排刷新；此后从页面新建缓存任务，进度可能停在初始值。现在列表每次刷新都会检查活跃任务，自动启动单一的低频进度刷新，完成或退出后停止。桌面规格覆盖从空闲到新建任务的状态变化；Kindle 休眠与长时间下载仍需实测。

若下载记录的本地存储暂时不可用，下载管理会显示错误码与“重新读取下载记录”，不会误称“暂无下载记录”。恢复失败可在原页重试；已载入的任务仍可见，恢复成功后可继续新建缓存任务。桌面规格覆盖失败再重试的页面流程，设备存储故障仍需实机确认。

从书架打开搜索后取消，现在会返回原书架页及筛选状态；从空书源管理点“搜索添加”后取消，会返回书源管理。搜索结果页再次输入书名使用当前搜索页面，取消回旧结果；旧请求仍在加载时，新输入框不会被迟到结果盖住。桌面导航规格已验证这些路径。

微信书架同步取得新书后若本地保存失败，会保留本次书架供当前使用，并在页面提示重启后可能恢复上次书架；旧的本地副本不会被损坏。书城“加入微信书架”远端成功后若本地保存失败，会在详情页提示；若完整书架暂时无法刷新，则保存并显示本地记录，提示稍后重试同步。用户离开详情后，迟到的加入结果不会在别的页面弹提示。桌面规格覆盖这些路径，真实设备的空间不足和只读状态仍需实测。

下载任务从“下载中”进入“正在取消”时，写入可能尚未结束。插件缓存和阅读缓存现在共用检查，在取消完成前均不允许清理；取消结束后可以正常清理。桌面缓存与下载规格 3 项、160 条断言通过。

从“找书 → 发现 → 站点分类”点“搜索书名”后取消，现在返回刚才的站点分类；继续返回依次回到发现和原书架页。桌面导航、发现、书架分组及按钮保护规格 4 项、93 条断言通过。

从书架“更多 → 检查更新”关闭进度页面，现在回到打开前的书架页并保留筛选；未结束的检查请求会取消。桌面书架分组与更新界面规格 2 项、37 条断言通过。

新建缓存任务时，如果书架读取失败，选书页会显示“书架读取失败”及错误码，不再误称书架没有可缓存的书；返回书架仍可用。桌面下载创建和下载界面规格 2 项、111 条断言通过。

微信书架首页大封面的“继续阅读”现在直接打开最近阅读的书；点封面仍进入书籍详情。两处共用同一阅读启动和错误提示。桌面微信书架、阅读及书城规格 3 项、33 条断言通过；真实账号的章节和历史进度仍需设备验收。

微信扫码等待中若离开微信书架，二维码弹窗现在会关闭，待处理的登录请求也会取消；正常扫码完成仍会自动关闭二维码。桌面微信登录、异步导航及书架规格 3 项、35 条断言通过。

本次完整 Lua 回归为 177 项通过、1 项因缺少外部 `sources/yuedu-260114.json` 样本失败，共 47,486 条断言。安装包清单与可重复构建检查、命名空间和敏感信息扫描通过。

下载任务处于“正在取消”时，操作菜单显示不可点击的“正在取消，请稍候”；排队和下载中的任务继续提供取消操作。下载及 KOReader 菜单专项 4 项、269 条断言通过；最新完整 Lua 回归为 177 项通过、1 项因同一外部书源样本缺失失败，共 47,490 条断言。

书架存储读取失败时，现在显示错误及“重新读取”按钮，不再误报空书架；重试恢复后直接显示原有书籍。书架专项 4 项、176 条断言通过；最新完整 Lua 回归为 177 项通过、1 项因同一外部书源样本缺失失败，共 47,495 条断言。

“找书 → 发现”和“书源与下载 → 书源管理”读取书源数据库失败时，会显示错误码及“重新读取书源”，不再把已有书源误报为未导入。恢复后在原入口显示书源；真正没有导入书源时仍显示原有导入引导。桌面规格覆盖失败、重试、恢复和离页旧按钮。

“找书 → 搜索”读取书源列表失败时，搜索结果页显示 `STORAGE_ERROR` 和“重试”，不再把故障当作没有匹配书籍。确实没有启用书源时，会提示到书源管理导入或启用书源。桌面规格覆盖故障、恢复重试和空书源两条路径。

阅读进度读取失败时，书架保留可打开的书籍，显示“重新读取”，暂时按原书架顺序显示全部，不将书误归为未读；恢复后重新按最近阅读排序。SQLite 书架优先一次读取进度，避免逐本查询。书架与存储专项 4 项、256 条断言通过；最新完整 Lua 回归为 177 项通过、1 项因同一外部书源样本缺失失败，共 47,512 条断言。

微信读书账号切换或退出登录后，当前微信书架会立即丢弃旧账号的封面和本地快照，并按新账号读取缓存；旧账号迟到的同步或加入书架响应不能重新插入旧书。切换后可重新点“同步书架”获取新账号记录。桌面规格覆盖两种迟到响应、换号后的重新同步及退出登录；真实账号切换仍需 Kindle 验收。

从书架第 2 页打开“更多 → AI 服务 / 插件缓存 / 设置 / 阅读回顾 / 关于”，返回会先到“更多”，再回到书架第 2 页并保留筛选。从完整设置进入 AI 服务或插件缓存时，返回仍到完整设置。桌面导航规格覆盖这些路径；“检查更新”完成或取消后仍直接回原书架页。

下载任务正在运行或取消中，以及任务记录读取失败时，“清理全部插件缓存”“清理阅读缓存”和“立即按策略清理缓存”现在都会停止，不会把读取失败当作没有下载任务。取消任务真正结束后仍可清理。桌面规格覆盖返回错误与抛出异常两种路径；设备存储故障仍需实机验证。
