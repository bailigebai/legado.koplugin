# 不亦阅乎 v0.10.45

2026-10-03。

## 本次改动

修复微信阅读《油炸绿番茄》从“作者简介”翻到“献词”时报 `INVALID_INPUT / 请求网页正文`。

目录中的 `tar=""` 表示该章没有图片资源包。Lua 把空字符串当作真值，旧逻辑因而将它误判为“微信章节资源包地址不受信任”，图片请求尚未开始就终止。本版只让空值走现有的直接图片下载流程；非空非法地址继续拒绝，保留原有图片、缓存和授权检查。已有目录缓存无需删除。

## 根因证据

- 设备运行 v0.10.44；10/03 11:11:39、11:12:11 的日志均记录目标第 3 章失败。
- 同次设备目录：书籍远程 ID `3300131225`，第 3 章“献词”远程章节 ID `137`，`resource_tar=""`。第 1、2、4 章已缓存，第 3 章尚未成功缓存。
- 用当前微信章节客户端和协议匿名读取第 3 章，得到两个可信图片标签。两张 PNG 均返回 HTTP 200，尺寸分别为 720×200 和 720×10；PNG 块校验及解压通过。
- 将实际章节 HTML 与同一空资源包字段传入旧图片流程，稳定返回相同 `INVALID_INPUT`，图片请求次数为 0。

公开文档和测试不包含账号凭据、完整书籍正文或图片副本。

## 验证

回归测试先复现空资源包错误，再验证直接下载两张图、两张图都生成可验证的本地引用、离线复用、保留图片地址中的服务端后缀，以及非空非法资源包的拒绝。保留已有可信资源包和异步取消测试。

192 项 Lua 测试、48,327 条断言全部通过；12 项官方 KOReader 宿主契约、37,894 条断言及官方 SQLite 检查通过。独立审查重跑旧模块确认用例准确失败，并核对实际章节、重复读取、第二张图下载中取消及错误处理，未发现遗留问题。

实际章节 HTML 与两张 PNG 通过修复后的生产图片服务和缓存流程，生成两个本地引用，重复读取无新增下载；桌面使用图片尺寸的解码边界替身，未执行 Kindle 的真实解码器。

已先备份设备上的 v0.10.44，再替换插件文件；重新读取的 145 个文件全部与本版安装包一致。安装包 SHA-256：`6f3b7a45a07efff11c55156259c13eba3e4eb164b784da2e41057b4ed7d97e11`。

实际 Kindle 显示和翻章结果仍需按以下步骤验收；开发测试及安装文件一致性检查不能替代实机阅读。
