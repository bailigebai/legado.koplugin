# v0.10.41：整本缓存与微信缓存目录修复

## 故障和改动

1. 默认离线缓存：KOReader 默认数据目录为 `.`，原代码把相对默认目录送入只接受绝对路径的缓存设置校验，导致离线缓存未初始化。改用官方 `getFullDataDir()`，数据位置与原目录一致，保留自定义绝对目录设置。
2. 错误丢失：详情页用 `and/or` 调用缓存和导出，Lua 只留下第一个返回值，把失败替换成占位文本，真实错误码消失。改成显式返回调用结果，整本、部分章节和 EPUB 失败都能保留真实错误。
3. 微信 `cache root identity changed`：插件长期记录目录 inode，却未保持目录引用。Linux FAT 的 `fat_build_inode` 在重建 inode 时分配新编号，KOReader 的 Kindle 启动脚本也说明设备存储的 FAT/FUSE 特点。修复为缓存对象存活期间持有只读目录句柄，以保持目录引用；目录被真正替换、出现链接或路径越界时继续拒绝访问，写入仍使用原安全事务。

第 3 项是匹配用户现象的根因推断；同次设备日志没有记录期望/实际 inode 轨迹，桌面模拟验证不能替代设备确认。[Linux FAT 实现](https://github.com/torvalds/linux/blob/master/fs/fat/inode.c)，[KOReader Kindle 启动脚本](https://github.com/koreader/koreader/blob/v2026.07.1/platform/kindle/koreader.sh)。

不清理或迁移既有书架、缓存、授权、登录及阅读进度。新增目录句柄随缓存对象回收自动释放，设置验证创建的临时缓存对象同样释放句柄。

## 设备验收

1. 安全弹出 Kindle，完全退出并重启 KOReader，确认版本为 0.10.41。
2. 使用默认缓存目录，缓存一本短书或从第 1 章到第 5 章；到下载管理查看章节数量和进度。断网打开已缓存章节，应正常阅读；部分缓存不会显示“整本已下载”。
3. 微信书架点击开始阅读，确认不再出现 `cache root identity changed`，继续跨章阅读；保留网络失败时的真实错误提示。
4. 自定义缓存目录可保留原设置。整本完成后的封面应显示已下载标记。若仍失败，记录错误码、发生时间、使用默认或自定义目录，并保留同次 `koreader/crash.log`。
