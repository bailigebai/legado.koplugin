# v0.10.52：划选摘录到 Obsidian

## 阅读时怎样使用

1. 长按正文，拖动选择想保存的句子。
2. 点“摘录到 Obsidian”。先保存在设备上，联网后后台同步。
3. 在“工具 → 不亦阅乎 → Obsidian 摘录”查看保存记录、待同步数量，测试连接或重试同步。插件阅读设置里也有相同入口。

适用于书源、微信读书的无感及原生阅读，以及 KOReader 普通本地阅读中可选中文字的 MOBI、EPUB、PDF 等格式。扫描图片不能直接选出文字时，本功能不提供 OCR。

笔记默认位于 `阅读摘录/不亦阅乎/书名-书籍标识/`。每条摘录一篇 Markdown，包含原句、书名、作者、来源、章节、位置、摘录时间，并留有“我的想法”。重复保存同书同位置的相同原句不会生成第二篇。已上传笔记的后续修改会保留。

## 配置接收端

采用已确认的 Wi-Fi 方案，需要电脑的 Obsidian 正在运行，Kindle 能访问电脑的局域网地址。

1. 在 Obsidian 安装并启用 [Local REST API](https://github.com/coddingtonbear/obsidian-local-rest-api)，启用 HTTPS；监听地址使用电脑的局域网地址。
2. 接收插件启用后会生成密钥和证书。开发者可用仓库 `scripts/obsidian_connection.py` 生成设备连接文件：

   ```text
   python scripts/obsidian_connection.py --vault "你的仓库目录" --output-directory "源码仓库之外的新目录"
   ```

3. 将生成的 `obsidian-connection.json` 和 `obsidian-ca.pem` 一起复制到 Kindle 的同一目录，例如 `documents/不亦阅乎连接/`。
4. 打开“Obsidian 摘录 → 配置连接”，选择 JSON，点“测试连接”。成功后摘录会自动排队上传。

JSON 中的 `folder` 可以修改为 Obsidian 仓库内的相对目录。连接文件含接收密钥，请单独保管，不放进 GitHub、公开安装包或共享笔记。设置中只保存连接文件路径，日志不记录密钥。

## 离线、失败和目标变化

- 断网时仍保存原句；重新进入摘录管理、再次摘录或手动同步可重试。每轮失败后停止，避免反复请求影响阅读。
- 发送前核验证书链和服务器证书指纹；不允许明文 HTTP 或重定向。
- 上传后响应丢失，重试先核对已有笔记的摘录标记，避免重复或覆盖修改。
- 同名笔记没有本条摘录标记时保留原笔记并报告冲突。
- 待同步记录绑定首次接收地址、证书和目录。修改这些目标信息不会把旧摘录自动发送到另一个目标，需要恢复原连接配置。证书更新时也须重新生成设备配置；旧证书绑定的待同步记录本期不提供重定向功能。

## 本次验证及边界

新增测试覆盖三种阅读入口、选区生命周期、持久保存、断网重试、重复摘录、上传响应丢失、笔记冲突、目标改变、TLS 证书拒绝以及管理界面的异步提示。另用 KOReader 官方 SQLite 检查真实落盘与重开。

当前电脑接收插件文件已安装并写入 HTTPS 配置，尚待开启 Obsidian 命令行界面、启用插件并真实写入读回。设备尚未连接，Kindle 的触控、局域网连接及证书支持也未实机验收。桌面测试通过不代表已完成以上验收。

## 你的验收方法

1. 书源、微信读书、本地 MOBI 各选一句，确认出现“摘录到 Obsidian”。
2. 有网时检查仓库相应书名目录，核对原句和来源；在笔记里写批注，再重复保存同一句，确认笔记不重复且批注保留。
3. 断网保存一句，重启 KOReader，确认“Obsidian 摘录”仍显示待同步；联网点同步后出现对应笔记。
4. 同步期间关闭窗口、继续翻页，确认阅读仍可操作。

资料：[官方接口](https://github.com/coddingtonbear/obsidian-local-rest-api/blob/main/docs/openapi.yaml)、[Obsidian 命令行说明](https://obsidian.md/help/cli)。
