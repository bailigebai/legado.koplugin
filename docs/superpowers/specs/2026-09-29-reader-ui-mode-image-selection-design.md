# 不亦阅乎：书架、阅读交互与微信随文评论设计

## 目标与已确认需求

在现有 KOReader 插件内完成统一的墨水屏界面。书架首页让最近阅读的一本书占据视觉重点，显示大封面和详细简介，其下只放四本书；第二页起每页十二本，三行四列。书架右上角提供书源、微信读书、本地三种模式。新书默认使用 Swipe 动画和无感阅读；微信读书的章节若含图片，自动使用能显示图片的原生阅读模式。微信读书阅读页可查看当前章节及段落的随文评论，书籍详情外层保留整本书评；读者可拖动选择文字后主动请求 AI 解释。

用户在 2026-09-29 确认采用“改造现有页面”方案，并确认随文评论与整本书评都要，整本书评放在外层。目标设备是 Kindle Paperwhite Signature Edition，设计与验收以 600×800 的原生控件布局作为最小基准，再检查设备实际分辨率。这里的“外层”指书籍详情里的整本书评入口；阅读器只展示当前章节或段落相关评论。

## 当前事实与参考

- `legado/ui/library_screen.lua` 已有首页 1+4 和后续 3×4，但首页主封面固定为 130×180，简介限制为 110 高、五行，剩余空间由空白填充。`presenter.lua` 只在书源和本地之间两态切换，微信书架需经过“找书”。
- `legado/ui/leko_reader.lua` 的新书动画默认为 `side_ripple`；`legado/lib/settings.lua` 的无感阅读默认已开启。`legado/lib/leko_text.lua` 遇到图片会报 `UNSUPPORTED_CONTENT`，目前需手动切换原生阅读。`reader_session.lua` 的原生路径把正文包装成 HTML 文件，尚无章节图片资源的下载、缓存和本地引用；仅切换模式不能证明图片可见。
- 独立阅读器长按只能取整行文字调用 AI。微信读书现有“阅读评论”入口读取整本书书评，缺少当前章节和段落的随文评论。
- [Moon](https://github.com/AnkioTomas/moon) 提供墨水屏首页、书架与详情的信息层级参考；其[最近阅读主卡片](https://github.com/AnkioTomas/moon/blob/main/book.koplugin/ui/desktop/home/views/recent_hero.lua)按可用高度确定封面宽度，返回首页时重读最近阅读数据。只借鉴清楚的主次关系、尺寸随空间变化和单一主要操作，不复制它的数据库、整套桌面或组件代码。
- 微信读书官方 [笔记接口说明](https://github.com/Tencent/WeChatReading/blob/main/skills/notes.md)给出了 `chapterUid`、`range`、`/book/underlines`、`/book/readreviews` 与 `/review/single` 的关系；接口能否覆盖用户账号中的每一条公开随文评论，必须在真实账号上验证。整本书评已有 `/review/list` 路径。
- 图标候选已经在 `docs/logo-research-0.10.37.md` 核对。继续使用现有原创 `assets/logo.svg`，统一其显示尺寸和黑白对比；不引入图标运行依赖。

## 方案比较

1. 只放大封面并重新排列当前按钮：改动最少，但三书架切换、图片模式和拖动选字仍缺失。
2. 搬入 Moon 桌面：外观接近参考，但产生第二套书库、导航、缓存和阅读设置，维护成本高。
3. **在现有 Presenter、Shelf、ReaderSession 和阅读器上增量改造：采用。** 页面逻辑和已有存储保留，布局由可用尺寸决定，微信能力通过现有适配层接入；逐阶段验证每个入口。

## 页面层级与按钮规则

### 三种书架模式

书架标题栏右侧只有一个“切换书架”按钮。点按打开三项菜单：书源书架、微信书架、本地书架；当前模式带选中标记。微信未登录时仍能进入微信书架，并在该页显示扫码登录，不把登录动作藏在其他书架的找书菜单里。切换时取消旧页未完成的封面和网络回调，每种模式记住自己的页码与筛选；删除或重新同步导致页码超出范围时回到最后一个有效页。从详情、评论或设置返回时回到发起操作的模式和页码。

三个模式不合并书籍身份：书源按原有书源 ID，本地按文件身份，微信按账号和远端书 ID。微信退出或换号后，旧账号封面、按钮和迟到请求不能在新账号下重新打开书。

### 首页与后续分页

每种有封面内容的书架首页先显示最近阅读的一本：左侧大封面、右侧书名/作者/进度及可滚动的完整简介，下面是“继续阅读”主按钮，再下面一行四本等大的小封面。600×800 布局的主封面目标至少 230×320，剩余高度优先分配给主封面和简介；小封面维持四列，不能因为主卡片增大而被挤出屏幕。没有封面的书仍显示同尺寸占位，长简介可滚动，不截断实际内容。首屏只占五本，第二页起每页十二本，固定三行四列；封面关闭时沿用现有文字书架分页。

最近阅读按真实阅读时间排序，时间相同保持原顺序。首页第一本变化后，主卡片随之更新。整本缓存完成角标继续位于封面右下角，部分缓存不得标为整本已下载。

### 全界面按钮布局

共用标题栏、返回、页码和主要操作的排列规则：首页只保留“找书、整理书架、书源与下载、更多”四组；详情将“开始/继续阅读”放在最显眼处；下载页优先显示任务状态和继续/取消；微信阅读页把当前章节评论放进阅读菜单，整本书评留在书籍详情。子页面不重复放整套主书架按钮。600×800 下按钮不得溢出、覆盖正文或重叠，文字截断时通过分组菜单显示全称；触控目标与现有 36 像素最小高度一致。返回路径在每页保持可预期，异步刷新不能把用户带回已经离开的页面。

| 页面 | 顶栏 | 内容区的主要操作 | 次要操作与底部 |
| --- | --- | --- | --- |
| 书源、微信、本地书架 | 左侧返回，中间模式名，右侧固定“切换书架” | 最近阅读卡片下只有“继续/开始阅读”；点封面进入详情 | 书源与本地页保留四组功能入口；微信页用“书城、同步、更多”，未登录时突出扫码；页码和翻页固定底部 |
| 搜索、发现、微信书城 | 返回、页面名；搜索入口在首行 | 结果或站点列表占内容区，封面点击进入详情 | 仅显示与本页有关的筛选、重试和翻页，不重复书架四组入口 |
| 书源与本地书籍详情 | 返回、书名；右侧“更多” | 封面、作者、可滚动简介；“开始/继续阅读”独占主要按钮 | 目录、缓存、来源、分类、小票、诊断放入“更多”，不与阅读按钮同级堆叠 |
| 微信书籍详情 | 返回、书名；右侧“更多” | 封面、作者、简介；“开始/继续阅读”独占主要按钮 | “加入微信书架”和“整本书评”作为详情中的两个明确次要入口，整本书评不出现在阅读内 |
| 目录及选择缓存截至章 | 返回、当前书名和任务说明 | 章节列表；缓存选择页把“第一章至本章”写在章节动作上 | 页码、上一页/下一页、输入章号固定底部；目录加载失败就地重试 |
| 下载管理 | 返回、下载管理；可新建任务 | 每项显示书名、范围、已完成/总数和状态 | 点任务只显示此任务此状态可执行的继续/重试/取消/打开；刷新固定底部 |
| 设置、AI、缓存维护与关于 | 返回、当前设置组 | 一个设置或状态占一行，保存/连接测试紧邻相关项 | 危险清理保留确认框，返回原入口；不显示书架功能组 |
| 微信扫码与评论 | 扫码页显示取消；评论页显示返回和当前书/章 | 二维码保持可扫尺寸；评论显示原文与对应想法 | 本章评论在阅读菜单进入，整本书评从详情进入；有续页时翻页固定底部 |
| 阅读正文 | 保持正文完整可见，顶部点按打开阅读菜单 | 翻页手势优先；长按拖动产生选区 | 目录、阅读设置、当前章节评论放进菜单；选区操作仅在选中后出现 |

这些规则覆盖所有通过 `LibraryScreen`、现有菜单及独立阅读器展示的主要页面；实施时逐一走真实按钮链，记录每页 600×800 的可视区域和触控区域。若某页因按钮文字过长而无法同时显示，先收进该页“更多”，不能缩小正文或把按钮挤出屏幕。

## 阅读行为

### 默认 Swipe 与图片章节

未保存动画偏好的书首次进入无感阅读时使用固定 `Swipe动画` 预设。已由用户按书保存的动画选择继续使用，不因更新覆盖。跨章仍采用现有完整绘制策略，避免恢复曾经的旧正文和黑边问题。无感阅读默认开关继续为开启。

微信读书在准备当前章节正文、创建阅读页面之前检查图片元素。若含图片，先把该书标为“已知含图片”，用同一章节及已保存进度打开 KOReader 原生阅读器，显示简短提示。以后打开此书默认原生阅读；其他微信书和书源书不受影响。后续章节首次出现图片时也按同一路径自动切换，不丢弃图片、不跳章。标记保存在该书的阅读状态中，不修改全局无感阅读设置。手动尝试为该书开启无感阅读时明确提示图片限制。

含图片章节必须把允许的微信图片地址解析并下载到该章节的受保护缓存，再将 HTML 中的图片引用改为本地文件路径。图片请求只向校验过的 HTTPS 来源发送所需会话信息，并限制单图大小、总量和可解码格式；缓存文件与章节绑定并校验完整性。图片获取失败时保留上一可读页面，提示重试，不以空白图片宣称章节已打开。离线打开时复用已缓存图片；图片缺失应明确提示，不能静默跳过。原生阅读器中实际显示图片、断网重开仍显示图片，均为设备验收项。

### 拖动选字与 AI

独立阅读器在正文长按进入选择状态，拖动起点或终点调整字词范围；显示当前选中文本和“AI 解释/取消”。只有点击“AI 解释”才按现有 AI 服务设置发送文本。选区不能跨越当前不存在的页面；切章、关页、菜单打开时清除选择。超过现有 4000 字节限制时提示缩短，不能截断后悄悄发送。原生 KOReader 阅读继续使用已有划词工具栏。单击翻页和左右滑动翻页保持原行为；拖动选择状态优先消费手势，避免误翻页。至少在 Kindle 实际触屏验证选区边界和高亮可见性，整行长按不能代替拖动选择验收。

### 微信随文评论与整本书评

阅读菜单增加“本章评论”，仅在微信读书会话中出现。列表按当前 `bookId + chapterUid` 读取，逐条显示对应原文摘要和评论内容；有 `range` 的评论可从该段正文标记点按进入，点击评论进入完整详情。无精确段落位置但带当前章节 ID 的评论列在本章列表底部。切换章节后列表更新，旧章节请求立即取消或被代际检查丢弃。接口无评论、离线或登录失效时显示明确状态，阅读正文不被阻断。仅以书名匹配的评论不得混入。

微信的 `range` 是原文位置，而独立阅读器把 HTML 清理并重排成段落和字符位置。解析正文时要保留原文位置到显示位置的映射，并用评论返回的原文摘要校验匹配结果；不能直接把 `range` 数字当成屏幕坐标或段落字符号。只有匹配到当前显示文本的评论才放正文段落标记。遇到版本差异、繁简转换或空白变化而无法可靠定位时，评论仍按当前章节及原文摘要列在“本章评论”，但正文不显示错误位置的标记。验收需有带标签、空白和多字节中文的定位样本，并在 Kindle 上核对同段落标记。

整本书评维持书籍详情最外层入口，继续提供分页和详情，不能作为“本章评论”的替代。公开随文评论优先使用微信读书提供的 `chapterUid/range` 与划线评论接口；个人笔记与公开评论在界面明确区分。真实账号验收时核对微信读书原应用中的同一书、同一章、同一段；若接口缺失某类评论，界面显示可用范围和错误，不把书评伪装成随文评论。

## 职责边界与错误处理

- `library_screen.lua` 只计算并绘制标题栏、主卡片、网格、按钮和触控区域。`presenter.lua` 决定模式切换、返回栈与每页动作；`bookshelf.lua` 与 `weread.lua` 各自提供排序和分页数据。
- `weread_client.lua` 负责评论协议和账号校验，`weread_mapper.lua` 将远端书、章节和范围映射为稳定身份；正文解析层保留位置映射，阅读器只接收当前章节且位置已核对的正文标记。AI 服务仍由现有 `ai_service.lua` 提供，手势层不保存密钥。
- 图片检测放在章节正文进入渲染器之前；微信适配层和缓存层负责图片的安全获取、本地路径及清理边界；ReaderSession 负责无感/原生候选切换、进度和失败回滚。每书“含图片”标志与阅读进度同一持久化边界，保存失败应可见，不能假装已经记住该书模式。
- 外部评论和 AI 请求均有上限、超时及离页取消；错误信息不包含会话凭据、原始请求头或 AI 密钥。公开评论只读，不在设备上代用户发表或点赞。

## 分阶段实施与验收

1. **书架和全局按钮：** 改 `presenter.lua`、`library_screen.lua`、`bookshelf.lua`、`weread.lua` 及对应规格。桌面原生控件检查 600×800 和设备分辨率，首页主封面实测至少 230×320、四本完整可见，第二页 3×4；三模式及返回路径走真实按钮链。
2. **阅读默认值和图片：** 改 `leko_reader.lua`、`reader_session.lua`、`app.lua`、微信正文适配、图片缓存及规格。验证新书 Swipe、手动偏好保留、首章与后续图片自动原生、相对和绝对地址的图片获取、无效地址与超限拒绝、失败回滚、离线图片章与跨章画面。
3. **随文评论与拖动选字：** 扩充微信评论协议、原文位置映射、阅读菜单及手势规格。验证当前书/章/段身份、HTML 清理后的精确定位与失配降级、分页、迟到响应、拖动范围、取消、AI 主动发送和正常翻页。
4. **设备验收与交付：** 在连接的 Kindle 上检查实际布局、触控、扫码登录后的评论和含图片章节；完整 Lua 规格、KOReader 原生控件契约、包清单和设备读回对比通过后生成安装包。真实微信账号及 AI 密钥相关路径以用户在设备上操作的结果为准，不把模拟测试写成实机成功。

设计完成不等于功能完成；各阶段只有满足对应运行证据才可标记完成。
