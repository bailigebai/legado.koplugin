# 第一期：章尾前三页预取与在途复用

目标：当前章剩余不超过三页时，下一章全部正文（包括网页分页）已经开始获取；章尾复用在途请求，完成后直接打开已准备的 HTML。保留预取章数 0 的关闭语义。

根因：`ReaderSession:_end` 取消后台请求，随后 `_fetch_then_open` 再发同一章；后台只写正文，章尾才生成 HTML。原生适配层未向会话转发 PageUpdate/PosUpdate。`BookService:getContent` 已负责汇总全部正文分页，无需另写分页器。

| 方案 | 改动及效果 | 选择 |
| --- | --- | --- |
| 只调短延时 | 无法避免慢请求在章尾被取消，也没有三页阈值 | 不选 |
| 复用现有串行预取，接入页更新并复用在途请求 | 最小范围，继续使用正文清洗、缓存和取消代际 | 推荐并实施 |
| 新建通用多级下载队列 | 需重构服务与优先级模型，超出本期 | 不选 |

范围：`reader_session.lua`、`koreader_reader_ui.lua`、专项 spec；既有 `reading_cache_spec.lua` 中“取消重取”的旧期望改为复用。保留每书 ReadSettings/SaveSettings 生命周期。

步骤及验收：

1. 先红：慢下一章请求在章尾不取消、不重取；三页触发时完整正文和 HTML 均可供下一章打开。
2. 增加原生页事件通知；保留原始事件分发、字体重排后的新页数；重复页事件不重复发请求。
3. 复用当前下一章请求；失败后释放章尾保护，允许下一次翻页重试；换书、关闭、离线、最后章不接受过期结果。
4. 不足目录时临近章尾加载目录，章尾复用同一目录请求后继续正文预取。目录不增长时不递归循环。
5. 运行专项测试及阅读会话、启动、原生事件、每书设置回归；主机测试不代表 Kindle 实机翻页耗时验收。

实机验收：设置预取 3，选慢书源，进入当前章倒数第四页再向后翻；剩余三页应开始/继续下一章请求，章尾不出现第二个相同正文请求。关闭预取、断网、末章和换书后分别检查行为。

实施与验证记录：

- 新增 `ReaderSession:onPageUpdate(state, document, page, total)`；适配器在原生 PageUpdate、PosUpdate、DocumentRerendered 分发后通知。首次打开保留 0.5 秒延迟，短章节在该延迟回调里补查页数。
- 下一章请求以当前会话和章节 UID 复用；完成正文清洗后提前写 HTML。复用记录只保存校验值、路径和标题，不保留整章正文副本。
- 补目录请求按会话合并，关闭目录弹窗只取消自己的订阅；关闭阅读器仍取消实际请求。未增长的目录、请求启动抛错、请求失败均不递归或阻塞重试。
- 一轮边界优化：前台已接管预取时停止旧后台链，等新阅读器 ready 后再调度；HTML 单独失败不重新下载已有正文。
- 专项先红证据：章尾复用断言原先 `expected 0, got 1`；旧后台链过早继续断言 `expected 1, got 2`；目录启动异常断言 `expected true, got false`；HTML 失败重复下载断言 `expected 1, got 2`。临时禁用原生页转发后，专项明确失败 `expected 1, got 0`，恢复后通过。
- `phase1_prefetch_spec.lua`：79 断言通过，使用真实 BookService 与解析规则验证首次缺缓存下载、正文网页分页，使用固定 KOReader 的 Event 验证原生页通知形状。
- 完整检查补查：真实 IO 暴露 BookService 第三个回调参数 trace 元数据被内部 cached 标记误认；新增首次无缓存回归先红 `expected 1, got 0`，将标记严格限定为 boolean true 后恢复。`spec/reader_document_io_test.py` 已通过真实正文写盘、HTML 文件打开及错误脱敏检查。
- `.tools/python/python.exe scripts/run_lua_specs.py`：101 组全部通过，42,575 断言（包含同期分类与背景测试）。每书阅读设置 70 断言与启动、缓存、旧回调回归保持通过。`git diff --check` 通过，仅已有工作区换行符提示。
- 尚未验证：Kindle 真机网络耗时、页面刷新耗时及慢站点实际等待上限。网络未能在三页阅读时间内完成时，章尾仍需要等待剩余下载时间，但不会丢弃已完成下载重来。
