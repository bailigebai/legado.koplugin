# 最近阅读排序与跨章卡顿排查计划

## 目标与事实

- 书架默认将最近阅读的书排在第一位；封面和文字模式、筛选及分页使用同一顺序。
- 用户反馈两种阅读模式均偶发跨章卡顿，约每 20 章一次。设备上还没有可复现的时间日志。
- `ReaderSession` 已在进度中保存 `updated_at`；书架读取进度但目前未排序。
- `CacheStore:_afterWrite` 每次缓存写入都安排 `_cleanup`；后者会递归扫描全部缓存文件，即使已知大小低于清理阈值。

## 方案比较

1. 仅调整书架和翻页界面：改动少，但无法消除两种阅读模式共用的缓存扫描。
2. 使用现有阅读时间排序，并仅在达到阈值时做后台缓存扫描：改动最小，保留硬上限和旧书淘汰规则。采用此方案。
3. 改成增量索引或重写整个阅读加载链：可能有更大性能空间，但需处理索引损坏、迁移和并发，当前证据不足。

## 阶段与验收

1. 在 `spec/compact_shelf_spec.lua` 增加最近阅读、未读和分页的失败测试，再修改 `legado.koplugin/legado/ui/bookshelf.lua`。同时间的书保持存储返回的顺序。
2. 在 `spec/cache_management_spec.lua` 增加多次写入但未达阈值的失败测试，再修改 `legado.koplugin/legado/lib/cache_store.lua`。达到阈值仍清理，硬上限仍拒绝超额写入。
3. 运行关联 Lua 规格、完整可运行测试和现有章节切换基准；检查变更边界及错误处理。实机约 20 章卡顿是否完全消失，需 Kindle 上继续验收。
4. 若验证通过，更新版本和发布说明，按用户此前指定的形式同步源码、安装 ZIP 和 GitHub Release。
