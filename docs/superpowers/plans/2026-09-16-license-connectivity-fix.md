# Legado 授权连通性核对与最小修复

用户在 v0.10.8 交付询问“是否继续部署备用授权入口”后回复“继续”，随后要求按独立授权方案对照其他可用插件排查。本轮保留该部署授权，先用当前代码和同网络对照确认原因，不改产品身份、签名密钥、已有密钥池或用户阅读数据。

## 已验证原因

2026-09-16 同机并行、禁用代理、保留 TLS 校验：Legado `legado-receipt-shelf-license.981998229.workers.dev/health` DNS 成功但 TCP 5.01 秒超时；推箱子 `ink-sokoban-license.pages.dev/health` 1.33 秒 HTTP 200。两个客户端 TLS 实现同源，主要差异是固定主机名。Legado 服务端与客户端 product 和签名规范一致；网络请求尚未到密钥判断阶段，不能将此次超时归因于错误密钥。未识别可用 Kindle。

## 三方案比较

| 方案 | 结果与代价 |
| --- | --- |
| A 保留 workers.dev，仅重试或延时 | 当前 TCP 不通，无证据能解决；不采用 |
| B 本产品独立 Pages + Service Binding | 推荐；沿用 Legado 独立 Worker/D1/签名，只有入口变化；不复用推箱子服务或密钥 |
| C 自有域名绑定 Worker | 可行但依赖用户域名、DNS与证书配置，当前无需引入 |

## 执行与验收

1. 读取本产品配置、已审查网关及其他可用插件；重复同机对照，核对部署状态。
2. 依已有授权部署 `legado-receipt-shelf-gateway`，仅 `LICENSE` 绑定现有 `legado-receipt-shelf-license`。新入口接受激活转发，会使用现有服务配额；不迁移数据库或私钥。
3. 禁用代理，验证 HTTPS/TLS 1.2、health、非法请求和真正签名授权；优先复验已有测试绑定。不得消耗待售密钥，测试签名/绑定材料不输出到报告。若需独立测试行必须与销售库存隔离并记录核验影响。
4. 通过后将客户端固定端点和 SNI/主机校验统一改为新域名；保留无跳转、超时、尺寸上限、设备绑定、离线验签和原子保存。补一条端点与产品隔离的回归，检查真实保存读回和错误分类。
5. 聚焦授权回归、完整发布检查、公开包秘密排除、可重现构建；v0.10.9 同步到 AA/dist 和工作区 dist，说明电脑验证与 Kindle 实机边界。

暂不迁移授权身份，不重发 1000/4000 个销售密钥，不删除现有授权。旧已激活离线 receipt 应继续有效。协议核对发现的问题必须分别记录，不把 HTTP health 成功当作真实签名/D1 成功。
