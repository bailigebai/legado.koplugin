# 微信无感阅读随文评论临时规划

## 目标

有公开想法的句子或段落显示黑色虚线下划线，点击原句打开对应随文评论。保留页边“评”入口，方便词典词条与评论重叠时选择。评论展示头像、姓名、正文和微信实际返回的数量，点击查看回复及点赞者；缺少数量时省略。只读，不发表想法或点赞。

## 方案比较

1. 仅使用现有页边“评”：改动最小，但缺少正文划线及完整评论详情。
2. 复用 underlines/readReviews、原句定位及现有讨论卡片（采用）：无需新依赖，复用取消、分页、头像缓存及详情功能。
3. 新建随文评论子系统：实现重复，增加维护负担。

## 阶段与验收

- [x] 数据与原句：`weread_client.lua` 保留外层真实点赞/回复数、可靠 reviewId；请求使用后台优先级。`weread_mapper.lua` 复用作者及数量校验。`leko_text.lua` 对原文范围与引文同时核对，支持跨段引文，版本不匹配不划线。测试错误书籍/章节/范围、重复引文、缺失数量、跨段和图片边界。
- [x] 阅读标记：`ui/leko_reader.lua` 使用已有 `leko_selection.rectsForRange` 的实际字形边界，缓存当前页划线，跨行/跨页连续显示。同范围去重，重叠点击收集所有范围。词典实线保留，词条文字点开词典；评论虚线及页边“评”点开评论。
- [x] 列表详情：`ui/chapter_discussions.lua` 接受随文模式及范围筛选，复用头像卡片和详情/回复/点赞者。`presenter.lua` 删除旧简单随文弹窗。`weread_comments.lua` 管理详情关闭。返回保留筛选和分页，加载更多只读已存在游标。
- [x] 生命周期：换章先取消可选评论 IO；关闭、换账号及迟到响应不能重开界面，不改变正文位置。断网/接口失败可重试，正文仍可阅读。

- [ ] 设备安装：设备识别后使用逐文件备份和读回校验安装；当前未识别到 Kindle。

## 边界与检查重点

接口仍按每次最多 10 个原文范围、每范围最多 20 条分页加载，不自动下载全书评论。未能与本版原文核对的评论只保留在列表中。图片、未知范围和旧账号不得生成错误划线；缺少真实 reviewId 的记录只能阅读全文。官方数据当前不可获取时须明确自动检查与设备验收的区别。

## 执行记录

基线 `c43737a`，现有开发分支 `codex/moon-integration`。依据用户明确新增功能授权，当前会话直接实施，完成后独立审查；无需重复询问功能授权。

独立审查及真实样本证明旧 `source_positions` 是去标签后的 Unicode 字符位置，微信 range 是完整原 HTML 的 UTF-16 位置。增加 `weread_text_coordinates.lua` 在客户端解码后保留文本 run 坐标，清理器只保留受限内部 span 属性，正文解析保存紧凑 run 并核对范围。无需改变缓存存储接口或新增依赖；旧缓存通过一次“刷新本章”取得坐标，避免为可选评论自动重下载已有正文。真实作者简介样本 18 条含引文记录中，17 条正文引文均可定位；另 1 条是已从正文移到标题的章名，保留在列表。

审查还发现横屏六张评论卡只能显示一行，原句占据了正文预览。原句改为可用空间足够时显示的独立单行，优先保留评论正文。

第二次审查补充了注解超缓存字节上限及实体循环重复查找换行的问题。增加 4 MiB 输出限额，超字节或 run 上限回退完整正文，缺少注解的微信模型明确使用空可信坐标表，不再回退旧坐标。缓存下一实体/换行位置及其缺失状态，避免二次复杂度；补测试验证完整 3.55 MB 正文回退、旧缓存与 run 限额不误标、530 KB 含 1,000 个实体的正文只扫描一次换行。相关旧测试改用真实原 HTML UTF-16 范围。
