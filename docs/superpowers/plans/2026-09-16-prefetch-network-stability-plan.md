# 下一章完整预读、跨章提速、联网与稳定性实施计划

> 执行说明：此计划已获用户批准并进入实施。初始排查证据保留在下文；本轮实现、宿主验收与实机缺口见 `docs/reader-library-0.10.8.md`，独立审查和修复记录保存在本计划的 `.superpowers/sdd/` 工作台。未部署线上网关。

**Goal：** 在阅读当前章时完整准备下一章，跨章复用已完成及在途工作；恢复 Kindle 联网激活的可靠性，通过多轮故障与实机检查减少退出、假死和界面掉回文件管理器。

**Architecture：** 延续 ReaderSession → BookService → RequestEngine → CacheStore 和原生/独立两个阅读适配器，不另起第二套下载、缓存或阅读管理系统。把预取任务生命周期从单章页面调整为同一本书的阅读会话，优先准备紧邻下一章；联网通过 KOReader 原生接口协调，授权继续使用现有签名协议。

**Tech Stack：** Lua/LuaJIT、KOReader v2026.07.1、现有 LuaSocket/LuaSec、已有子进程适配器、SQLite/原子文件存储、现有 Leko 衍生分页模块。

**Spec：** 本次用户要求“当前章阅读期间完整加载下一章、跨章响应快、完整计划、全插件多轮稳定性排查、打开插件后网络断开且无法验证短密钥”；基线为当前工作区及已交付 v0.10.7。

## 全局约束

- 默认书源和自行导入继续可用；短密钥只锁定小票、阅读回顾数据展示，书架数量不限。
- 不改产品标识、RSA 公钥、既有授权数据、密钥池和设备绑定规则。
- 不清空书架、阅读记录、用户设置和有效缓存；缓存淘汰继续遵循 500/300/200 MiB 默认规则。
- 不通过加大并发、延长所有超时、永久关闭系统省电或关闭 TLS 校验掩盖问题。
- 不把原生 ReaderUI 同时打开两份作为预热方法；其单例与全局钩子目前不适合双实例。
- 不通过全屏透明遮罩吃掉输入；旧正文或插件背景由明确的页面所有者保留。
- 新增日志不得包含短密钥、签名授权全文、设备原始序列号、Cookie、认证头或网页正文。
- 现有目录 24 章双列、翻页按需加载、状态最多每 6 秒合并刷新继续保留；6 秒仅限制显示刷新，不延迟网络任务启动。
- 工作区含大量历史修改，只调整本计划所需文件，不重置或提交整个工作区。
- 如需新增 Pages 入口或修改线上服务，先准备可审查代码与测试，部署前单独确认影响；本计划本身不部署。

## 一、已完成排查：事实与推测分开

| 项目 | 当前证据 | 结论范围 |
| --- | --- | --- |
| 已有预读 | `reader_session.lua:199` 在章页就绪后 0.5 秒安排预取；`:652` 有剩余 3 页触发机制 | 预读并非完全没有实现，继续重复增加触发器不是根治 |
| 跨章取消有效任务 | 基于 `spec/phase1_prefetch_spec.lua` 的现有 fixture：第 2 章完成、第 3 章在途时从第 1 章切到第 2 章，第 3 章取消次数为 1，请求次数为 2 | 已在宿主复现；`:199` 的取消与 `:681` 的章节状态绑定会浪费预取工作 |
| 目录缺失时未马上预读 | 初始目录只含当前章且未完整时，执行首次预取 tick：目录请求 0、正文请求 0 | 已复现；需等 6 秒目录任务或接近章末，无法保证立即准备下一章 |
| 完整正文抓取 | `book_service.lua:634` 顺序抓取 `nextContentUrl`，最多 20 页，最后统一回调 | 可复用；须验证分页规则正确、总字节上限和半章失败，不应把截断内容标为完成 |
| 缓存后仍有打开开销 | `reader_session.lua:363` 原生调用 `openDocument`，独立调用 `openChapter`；`leko_reader_ui.lua` 重新创建阅读 widget | 正文下载完成不等于下一章首屏已经准备好；具体耗时需分段实测 |
| 主线程磁盘扫描 | `cache_store.lua:98` 每次写入调用容量清理；正文与 HTML 写入都可触发目录扫描 | 已确认代码路径；是否为本机卡顿主要来源需测量 |
| 网络控制 | 当前插件 Lua 运行代码没有 `turnOffWifi/disableWifi` 等调用，也未接入 NetworkMgr 联网准备 | 不能据此证明设备未断网；目前没有证据证明插件直接关闭无线电 |
| 授权阻塞风险 | `presenter.lua:929` 调用同步激活，`:933` 只有 `trapper:wrap`；官方 Trapper 的 wrap 仅创建协程 | 同步 socket 没有主动让出 UI，可造成最长超时期间无响应，协程不等于后台线程 |
| 授权地址直连 | 本机禁用应用层代理：书源 HTTPS 返回 200（0.88 秒），授权 Worker 在 TCP 阶段超时（5.02 秒）；另一次健康探测也超时 | 证明当前电脑网络存在授权入口连通性问题，不等同于 Kindle 网络原因或所有地区均不可达 |
| 实机证据 | 当前未识别到 Kindle 可访问卷/WPD；本地 Kindle 日志最后采集于 9 月 14 日 | 旧日志出现其他阅读插件的 Wi-Fi 恢复记录，只能提示共存排查方向，不能判定本次责任 |

本轮已运行 5 组既有规格：预取、原生启动失败、独立事件边界、独立设置异常、授权，共 228 条断言通过。上述跨章重复请求仍可复现，说明现有通过用例没有覆盖该状态组合。它们不是本轮修复完成证据。

## 二、三个方案比较

| 方案 | 具体做法 | 优点 | 代价与判断 |
| --- | --- | --- | --- |
| A：提前触发当前预取 | 只把倒数 3 页触发改到当前章打开时 | 改动最小 | 无法解决跨章取消、抢占排队、阅读器重建和网络失败；不推荐单独采用 |
| B：统一会话预取，分层准备下一章 | 修正已有任务归属、优先级、落盘与首屏准备；原生和独立分别优化；联网与故障治理分阶段实施 | 复用现有基础，改动可逐项验证，保持两种阅读模式 | 推荐；原生引擎仍有重新打开文档的固有成本，需要实机计时 |
| C：改成长文档连续阅读 | 多章合并为可追加文档，目录、统计、页数和进度统一按整本维护 | 有机会消除原生按章打开的成本 | 影响目录定位、书源切换、统计、排版与恢复，返工风险最大；仅 B 实测不达标且确认必要时再独立评审 |

推荐 B，执行顺序：联网和日志 → 下一章完整预读 → 两种阅读器跨章优化 → 全插件多轮回归。每一步有自己的退出条件，不同时堆入所有改动。

## 三、目标使用流程

1. 当前章首屏显示、会话正式就绪后，立即把“下一章完整正文”排为高优先级任务，不等倒数 3 页。
2. 缺少下一章目录条目时，只先补充取得下一章所需的目录页；下一章正文不等全部目录完成。
3. 下一章的多个网页全部解析成功、内容校验通过并原子落盘后，才标为“正文就绪”。缓存失败或分页失败不伪报完成。
4. 原生模式提前准备合法 HTML；独立模式提前准备文本结构和第一页分页结果。余下页码计算分批进行，不阻塞当前章翻页。
5. 默认预取 3 章：先完整准备下一章，再顺序准备后两章；后两章不得阻塞下一章或用户显式跳章。0 继续表示关闭自动预取，主动跳章仍可加载。
6. 到章末：已准备则本地切换；正在准备则加入原任务等待，不取消重下；失败则保留当前正文，提示重试或换源。
7. 用户换书、换站点或退出后，旧结果不得写入新书状态或把页面拉回；同书顺序切章则保留仍需要的预取任务。
8. 预读状态只在已有状态区域显示“准备中/下一章已准备/失败”，不新增常驻大面板；自动刷新最多每 6 秒一次，不触发整页闪烁。

## 四、阶段 0：定位断网并恢复联网激活（最高优先级）

**修改范围：** `legado/ui/bootstrap.lua`、`legado/ui/presenter.lua`、`legado/lib/license.lua`、`legado/lib/license_transport.lua`；如确需通用协调，新增一个小型 `legado/lib/network_access.lua` 由联网操作复用，禁止重复造连接池。

**使用现有接口：** `NetworkMgr:isWifiOn/isConnected/runWhenConnected`、KOReader 联网提示、`StandbyGuard`、现有子进程工具。先核对当前实际 KOReader 版本可用的方法，不直接改官方源码或全局联网设置。

- [ ] 取得同一次复现的时间线：KOReader 启动、Wi-Fi 已连接、打开书架、打开密钥框、点击激活、出现失败；关联无线电、IP/连接状态、系统省电、暂停/恢复事件与错误阶段。记录模式、插件版本及其他已启用插件名单，不记录密钥和网络凭据。
- [ ] 分别复现：无线电关闭、Wi-Fi 开但未连上、已连接但 DNS 失败、TCP 不通、TLS 失败、HTTP 错误、签名错误、保存错误。错误提示与诊断必须区分。
- [ ] 在用户点击“联网激活”时通过原生接口准备网络，连接成功后仅启动一次请求；取消联网提示不得消耗密钥、弹出后台页面或重复重试。单纯打开插件不强制开关 Wi-Fi。
- [ ] 将阻塞的 HTTPS 请求移出 UI 执行路径。子进程只处理请求，主进程完成设备标识读取、签名验证、原子保存与读回确认，避免子进程保存设置后主进程内存仍旧。
- [ ] 保留 HTTPS、CA 与主机名校验、禁止重定向、512 字节请求/8192 字节响应边界和超时；不以关闭安全校验修复连通性。
- [ ] 网络任务期间使用成对、可取消的保活；成功、失败、超时、取消、页面关闭和挂起均释放。若证据确认自动关闭 Wi-Fi 定时器冲突，再采用与当前版本兼容的临时协调，不永久更改用户省电偏好，也不定时强制重新开网。
- [ ] 对授权入口进行 Kindle Wi-Fi 直连探测；若现有 `workers.dev` 在目标网络不可达，准备可选 Pages Service Binding 转发入口。仅转发到本产品原 Worker，不复制密钥池、数据库或私钥；新地址须实测健康与授权再进入安装包。需要部署时先单独确认。
- [ ] 增加 `spec/network_access_spec.lua`、`spec/license_activation_flow_spec.lua`，扩展 `spec/legado_license_spec.lua`；模拟网络回调重复/迟到、返回前关页、挂起、超时后重试、保存失败及重启离线授权。

**验收：** Wi-Fi 原本连接时，打开/关闭插件 20 次不触发插件主动关网；激活界面可响应取消/返回；网络已断时给出原生连接流程；已激活离线可用；未授权书架和普通阅读始终免费。真实授权需使用明确的测试密钥与独立测试设备记录，不用用户待售密钥作批量压力测试。

## 五、阶段 1：完整预读且不重复下载

**修改范围：** `reader_session.lua`、`book_service.lua`、`request_engine.lua`、`cache_store.lua`，必要时同步 `settings.lua` 的文案；复用现有配置，不增加第二套预取数量。

**任务身份：** 使用现有 source/book/chapter 标识，并以会话代次隔离换书、换源、刷新；任务归属不再因同书切章改变。资源版本/正文校验值用于判断缓存是否过期，不能仅按章节序号合并。

- [ ] 将本轮两个复现写成正式失败回归：下一章已完成、再下一章在途时切章不能取消后者；目录暂缺下一章时首屏后的预取必须立即请求必要目录。
- [ ] 同一章节只有一份有效在途请求；原生章末、独立下一页、目录跳转都订阅它。显示需要的章节升为前台优先，但不重建已经进行的同章请求。
- [ ] 使用既有 RequestEngine 队列实现少量明确优先级：用户当前阅读/跳章 → 紧邻下一章 → 其余预取/目录/封面与批量搜索。维持当前并发上限，测试低优先级任务也能继续，不靠大量并发提速。
- [ ] 在逐页正文抓取过程中累计字节数，超过现有 4 MiB 正文上限即安全退出；保留 20 网页分页上限和循环检测。缺失页、重复页、空正文、乱码、写盘失败均不标为完整。
- [ ] 保留原子缓存写入和内容校验；“正文就绪”和“可显示首屏”分别记录。预取 0 时不自动请求，缓存存在则复用，刷新或换源时正确失效。
- [ ] 下一章失败后只允许有界重试：当前会话自动重试一次；返回阅读、网络恢复或用户点重试可再发起。后台失败不反复弹框，不因重绘创建多个重试。
- [ ] 避免每个正文/HTML 写入都同步扫描全部缓存。把容量统计与淘汰合并到空闲调度，使用写入字节更新已知用量；接近上限时重新核实并受控清理，未知/超限状态不可当作允许无限写入。保护当前章、下一章准备结果与在途文件。
- [ ] 扩展 `spec/phase1_prefetch_spec.lua`、`spec/request_concurrency_spec.lua`、`spec/book_service_spec.lua`、`spec/cache_management_spec.lua`；加入真实多网页正文样本，测试被拒绝、取消、目录扩充、存储失败与模式切换。

**关键失败用例示意（沿用既有 fixture）：**

```lua
local f = fixture()
f.open(); f.scheduler:runNext()
f.finish(1, '<p>Second chapter complete</p>') -- 第三章进入下载
f.next(); f.scheduler:runNext()
eq(0, f.requests[2].cancelled, 'same book keeps useful prefetch')
local chapter3 = 0
for _, request in ipairs(f.requests) do
    if request.chapter.uid == 'c3' then chapter3 = chapter3 + 1 end
end
eq(1, chapter3, 'chapter 3 is fetched once')
```

**验收：** 当前章首屏后即可观察到下一章任务启动；下一章缓存成功后断网也能切入；连续 30 次跨章没有“切章取消后又重新请求同一章”；目录分页不完整时能先读紧邻下一章；半章失败永不当作就绪。

## 六、阶段 2：跨章快速展示，保留当前页面直到新章就绪

**修改范围：** `reader_session.lua`、`koreader_reader_ui.lua`、`leko_reader_ui.lua`、`ui/leko_reader.lua`、必要的 `leko_text.lua/leko_paginator.lua`、Presenter 页面背景管理。

- [ ] 先分段计时：排队、目录取得、下载、清洗、落盘、读取缓存、文字解析/首屏排版、引擎打开、首次绘制及物理屏幕可见。分别记录冷缓存/热缓存、原生/独立，避免把全部时间归为网络慢。
- [ ] 原生：跨章复用已准备 HTML、按书排版与封面元数据；避免非必要的重复清洗/全库扫描；旧正文或插件背景保留至新 reader ready。检查失败回滚、全局钩子恢复，禁止落入缓存文件管理目录。
- [ ] 独立：提前生成下一章的文本结构及第一页分页数据，复用现有页面容器切换内容；提交章节、位置、正文必须成组成功，否则保留旧章。避免为预热创建第二套活动菜单、时钟和刷新任务。
- [ ] 首屏准备结果带排版指纹：书源与章节、正文校验值、字体、字号、行距、页边距、屏幕方向和尺寸、页眉页脚占用。指纹不匹配时只重做排版，不重新下载正文。
- [ ] 预热最多一章的文本/首屏，后续只保留磁盘正文；不把三章完整位图常驻内存。其余分页分批，当前输入优先，取消与退出能终止任务。
- [ ] 跨章去重点击；读取进行中不出现“按钮消失但无说明”。未完成时显示轻量等待与重试入口，不自动跳回书架或文件管理器。
- [ ] 保持章内进度、下一章起点、书源匹配、统计、背景图、页眉页脚和书本排版设置的正确性；动画失败只降级该次动画，不能阻断正文切换。
- [ ] 扩展 `spec/phase3_session_spec.lua`、`spec/phase3/leko_reader_core_spec.lua`、`spec/native_reading_flow_spec.lua`、`spec/reader_startup_failure_spec.lua`、`spec/book_reader_settings_spec.lua`；覆盖修改字号/旋转后使用旧预热数据、旧回调迟到、连续点击、候选绘制失败。

**初始性能验收目标，不是当前实测承诺：**

| 场景 | 目标 |
| --- | --- |
| 当前章就绪到下一章任务入队 | 首次可调度时即入队；无争用时 500 ms 内开始，不能等剩余 3 页 |
| 点击响应 | 有阻塞等待时 150 ms 内给出软件层响应，不等待网络超时才绘制反馈 |
| 热缓存、首屏准备有效，独立跨章 | 30 次记录 P50/P95，P95 目标 ≤500 ms（到提交可绘制首屏） |
| 热缓存，原生跨章 | 30 次记录 P50/P95，P95 目标 ≤1.5 s（到引擎 ready/首屏提交） |
| 实际墨水屏 | 另计屏幕可见耗时、闪烁与触摸；不将软件提交时间冒充物理显示时间 |
| 弱网且预读未完成 | 复用在途任务，保留正文与清晰状态，不承诺网络未完成也能瞬开 |

若目标未达到，按最长耗时段继续优化并重新测量；不能用降低测量标准或桌面速度宣称 Kindle 已达标。若原生引擎打开成本构成无法消除的瓶颈，再单独讨论方案 C。

## 七、阶段 3：全插件四轮稳定性门禁

| 轮次 | 操作与故障范围 | 通过条件 |
| --- | --- | --- |
| 1：功能与路径 | 书架、搜索、发现、书源、本地目录、详情、目录、下载、设置、分类、换源、阅读回顾、小票、授权；两种阅读模式分别执行打开/返回/取消/确认，每条实际可达路径至少 3 遍 | 无未处理异常、错误页面残留、重复窗口、退出插件或回到缓存目录；校验真实状态，不能仅检查 callback 可调用 |
| 2：异常与竞态 | 每类用确定时序复现：DNS/TLS/HTTP、空/坏正文、存储只读/空间不足、断网恢复、取消后返回、换书换源迟到、目录页缺失、字体/图片/动画失败、计时回调发生在关闭后 | 旧任务不得更新新会话；错误提示可关闭；当前页、进度与设置可恢复；句柄与任务释放 |
| 3：连续压力 | 宿主/模拟环境连续跨章 500 次、菜单与返回 200 次、模式切换 50 次、挂起恢复事件 50 轮；包含长章和大目录 | 没有进程退出、失去输入、子进程/文件句柄遗留；RSS/Lua 内存及任务数没有随轮次持续线性增长，末尾能重开并保留进度 |
| 4：Kindle 实机 | 正常 Wi-Fi、断网、弱网、两种模式各连续阅读至少 60 分钟；打开退出 20 轮、睡眠唤醒 20 轮、真实跨章计时与一次测试授权及离线重启 | crash.log 无新未处理异常；没有内存杀进程/原生崩溃；不露出 FileManager；实体触摸、刷新、联网页面和离线授权均通过 |

**必须重点审查的边界：**

- `safe_event/xpcall` 只能捕获 Lua 错误，不能捕获原生段错误或内存耗尽；FFI、字体、图片、绘制与动画 buffer 的生命周期必须单独审查。
- `paintTo`、后台分页 batch、时钟任务和 RequestEngine 回调也属于入口，不能只防菜单点击。
- 关闭、取消、失败回滚幂等；引用已释放控件、重复 `free`、未恢复全局 ReaderUI 钩子和悬挂后台任务作为发布阻断项。
- 所有写入应先确认成功再切换可见状态；进度、授权与分类保存失败不能显示成功。
- 增量记录会话代次、章节匿名标识、阶段时间、错误代码、窗口/任务/子进程计数和内存快照；故障日志限长且脱敏。
- 其他插件共存与仅启用 Legado 做对照。只在用户同意的实机测试中临时调整其他插件，恢复原配置，不直接归咎 Moon/MiuRead。
