# 大书源合集导入验证 v0.10.30

2026-09-24。用户提供的15份文件大小为5,794,068–8,528,873字节，全部超过旧版5MiB上限；旧生产导入器逐份返回RESPONSE_TOO_LARGE。隔离测试放宽上限后，全部通过原严格JSON解析。照片中的泛化STORAGE_ERROR未在Kindle重现，不能单凭照片断言设备存储空间不足。

本版将书源导入、显式网络请求和进程传输上限同步至16MiB（传输额外保留128KiB封装空间）；普通网页默认仍为4MiB，超限继续拒绝。保留原事务和数据存储位置，不执行导入书源中的JavaScript，不修改授权。

通过本地导入入口、未修改的KOReader LJSQLite3及SQLite 3.45.1验证两组场景：每份导入空数据库；从已有919源开始连续合并全部文件。每轮包含首次导入、关闭重开、逐字段核对、重复导入、停用状态、UI列表、原书架和进度保留，以及无效导入不覆盖旧数据。

30轮场景全部通过。连续合并后得到 **3331 个不同站点地址的书源**。测试将原文件逐字节复制到临时目录，以绕过Windows Lua标准I/O对中文文件名的限制；Kindle端使用实际文件选择器。原文件内容没有修改。

复测脚本：`spec/source_collections_test.py INPUT... --baseline OLD.json --report REPORT.json`。输入可为JSON文件或目录；报告仅含文件名、体积、SHA256、计数与状态，不包含网址、Header/Cookie、规则正文。私有书源不入仓库或安装包。

用户验收：覆盖升级并重启KOReader → 更多 → 书源管理 → 从本地JSON导入 → 长按选择文件并确认。第一次显示新增/更新；再次导入不应重复增加；退出再进应保留。无需删除旧书源或重新激活。

边界：桌面测试证明这些文件能解析、保存和合并；尚未验证用户设备实际磁盘状态、内存峰值或导入耗时，也不代表每个网站当前可访问、所有阅读规则都兼容。
