# v0.10.8 预读、跨章与联网稳定性验证包

本版执行 2026-09-16 已批准方案 B。默认书源、自行导入、免费阅读及现有授权范围不变。升级只替换插件代码，不删除用户数据。

## 本次修改

- 当前章显示成功后，下一个 UI 调度立即开始完整预读下一章；目录不足时先取所需条目，不等待完整目录。默认预读 3 章，设为 0 仍关闭自动预读。
- 同书切章保留仍有用的在途请求；章末加入原请求并提高优先级，不重下半章。前台读取、紧邻下一章、远期预读依次排队，维持并发上限。
- 多网页正文必须全部完成，累计不超过 4 MiB；空页、循环、超过 20 页及写盘失败不伪报整章完成。网络错误最多自动重试一次，用户主动操作可以再次尝试。
- 独立阅读提前准备下一章文本和首屏；字号、方向、屏幕尺寸等变化会令旧排版失效。原生模式复用已准备的 HTML。保留旧页至新页显示并提交成功，错误时回退。
- 修复成功切章后的旧会话引用链、字体测量释放遗漏、等待框重复释放；保护绘制、后台分页、时钟及动画入口。动画失败降级，不撤销已成功打开的新章。
- 缓存写入按字节记账并合并空闲整理；接近硬上限先核实容量，同时保护当前书和正在准备的新书。默认仍为 500/300/200 MiB。
- 点击联网激活先调用 KOReader 原生网络准备，再在子进程执行 HTTPS。父进程验签、原子保存并读回；等待时可取消，关页、挂起、超时及迟到结果均受控。保持证书及主机名校验，不更改 Wi-Fi 省电偏好。

## 使用与验收

1. 完全退出 KOReader，解压包内 `legado.koplugin` 到 `koreader/plugins/`，替换旧代码，保留 `koreader/legado` 数据及设置。重启确认版本 0.10.8。
2. 预取设 3，联网读一章，稍等正文预取完成后断网翻到下一章；检查内容完整、目录位置正确。两种阅读模式分别验证。
3. 连续点下一章、从目录跳章、切换字号、返回书架，再打开同一本书；失败时原章应保留，不应露出缓存文件管理器。
4. 激活等待期间点按等待提示、返回或休眠，应能取消。断网时点击激活应进入 KOReader 连接流程。已有授权离线重启仍应有效。
5. 新日志中的 `[LegadoTiming]` 仅记录阶段、毫秒和阅读模式；需要启用 KOReader debug 日志。它记录缓存、HTML、前台正文等待和 reader ready，不含书名、正文或密钥，且不是物理墨水屏完成时间。

## 证据与边界

电脑规格使用生产 Session、Adapter、独立控件和固定 KOReader 官方生命周期代码，字体、屏幕、原生文档引擎及网络含平台替身。真实书源抽样使用生产解析/缓存流程，但 HTTP 和编码由电脑提供，不证明 Kindle TLS 连通性。

独立阅读复用下一章文本及首屏，仍构建候选 widget 后显示和提交，避免原地改写带来的失败回滚风险；原生仍需打开章节文档。这是对原规划“复用同一页面容器”的安全调整。

没有找到可用的物理 Kindle；两种模式各 60 分钟、20 次打开退出/休眠唤醒、硬件内存与刷新、真实授权和实机跨章 P50/P95 仍待验收。Lua 异常保护不能保证消除原生段错误或系统内存杀进程。

当前授权 Worker 地址未更改；电脑直连曾在 TCP 阶段超时。代码已解除 UI 同步阻塞并接入原生联网，但不能据此声称已解决所有网络的授权可达性或已经查明设备关网原因。可选 Pages 转发需另行部署批准与直连验收，未放进本安装包。

## 实施决定与代价

- 沿用已有隔离工作区，按上一交付包比对本轮代码；保留历史未提交文件。审查依据是交付包差异，不能把整个 git 差异视为本轮改动。
- 新章复用文本和首屏，仍使用候选页面验证后替换。这样保留失败回退；代价是原生及独立仍有页面创建成本，需实机计时确认。
- 可选联网网关仅准备代码，不部署、不切换客户端地址。代价是原授权域名无法直连的网络本轮仍可能激活失败；上线需单独确认后验证。

## 本轮宿主验收记录

- 完整 `scripts/run-specs.ps1`：129 组 Lua 规格、44,565 条断言通过；命名空间、真实 HTML 文件、HTTP 测试、EPUB、打包白名单、可重现构建、恶意 ZIP 与版本错配检查通过。
- `scripts/check-koreader-compat.ps1 -Offline`：固定 KOReader v2026.07.1 的 32 个模块契约、12 组原生流程和 37,875 条断言通过；官方 SQLite 真实读写与回滚检查通过。
- 13 组按钮/菜单/搜索/书架/目录/设置/换源/阅读回顾/授权相关规格各跑 3 次：39 组、1,077 条断言通过。用例覆盖路径不代表任意设备与操作组合均已证明无崩溃。
- 压力：500 次跨章（含 100 次真实 App 目录入口）、200 次菜单返回、50 次模式切换、50 次挂起恢复，1,719 条断言通过；关闭后无插件窗口或调度任务。
- 100/200/300/400/500 次跨章后 Lua heap 为 2051.73/2053.74/2065.57/2067.97/2059.87 KiB，无持续线性增长。LuaJIT 保留首轮两个纯 Lua 目录常量，测量完成后清 trace 并 GC，弱引用全部释放；选择句柄与活动资源独立检查。
- 宿主 CPU 跨章 P50/P95 为 21/23 ms，含上述测试替身；这不是 Kindle 墨水屏显示耗时，也不能据此断言实机达到规划性能目标。
- 220 个 Lua 文件语法检查通过。919 条默认配置已用官方 SQLite 保存、重开和重导入比对，无重复。

审查先复现并补测了三个边界：较远预取被重下、目录选择绕开复用、原生保存失败仍跳章。本版都已修正；保存失败时保留旧正文和待保存进度，目录取消仅撤销该次跳转。

原生缺失模块故障规格会主动输出“legado.missing”诊断；日志中该提示是故障注入的预期结果，须结合最后的通过计数和退出码判断。
