# 0.3.1 封面书架与阅读文件修复

## 操作

退出 KOReader，将安装包中的 `legado.koplugin` 放入 `koreader/plugins/` 更新代码，保留个人数据和设置。重启后在“工具 → 书源阅读 → 更多 → 关于”确认版本为 0.3.1。

- 默认首页打开全部收藏，每页 4 列×3 行。每格只显示封面及下方书名，封面缺失保留占位。
- 缩小字号、使用圆角按钮、去掉书格闲置黑框；按键选中时仍有黑色焦点框，格子尺寸不会变化。
- 顶部“全部 / 在读 / 未读”按插件保存的阅读进度筛选；“分类”使用已收藏书籍的类型，支持未分类。分类后再分页，返回详情或二级菜单时保留页码和分类。
- 底部保留翻页与紧凑主要操作。书源管理、下载、设置、关于以及本页次要操作位于“更多”。
- 点封面进入独立详情，显示较大的封面、作者等信息和完整简介；长简介可以滚动查看。开始阅读、收藏、目录、换源及下载继续可用。
- 正文失败时显示失败阶段，并可进入“更多 → 阅读诊断”，不会把原始网址、凭据或内部异常直接展示给用户。

## 阅读问题定位

旧版的 `CacheStore:writeHtml` 复用了正文缓存的通用写入方法。这个方法会添加 JSON 校验包装，因此扩展名虽然是 `.html`，实际文件却以 JSON 开头。它不应直接传给 KOReader 的文档加载器。之前的网页探测只验证到正文解析，未检查交给阅读器的实际文件字节，遗漏了这一步。

另一个已复现问题发生在首次阅读：章节未缓存时，下载已经正常启动，但旧代码仍把缓存不存在的 `STORAGE_ERROR` 返回给界面，界面提前结束请求，迟到的正文结果因此被忽略。本版下载启动后保留等待状态，只在实际失败时返回错误，新增延迟回调测试覆盖这一顺序。

本版将阅读用 HTML 与内部缓存格式分开：书源规则提取网页正文，清理后保存章节缓存，再生成 UTF-8 HTML 阅读文件并交给 KOReader。纯文本正文按换行保留独立段落，已有 HTML 结构保持不变。正文和目录缓存继续保留原有完整性校验与原子写入保护；不通过删除用户数据库修复。已有章节缓存可复用，重新打开书时重新生成阅读文件。

若正文已下载、但阅读文件无法写入，错误会回到详情页并显示失败阶段，不再静默中断；旧的有效阅读会话仍保留。

参考 Legado_Max 的搜索、章节正文获取与正文缓存分工，以及 Moon 的 `book/open.lua`、`ui/reader/session/chapter.lua`。同时核对固定 KOReader v2026.07.1 的 `ReaderUI:showReader(file, provider, seamless, is_provider_forced, after_open_callback)` 实际签名及就绪回调。HTML 和 TXT 都由原生阅读器排版；本插件保留合法 HTML 以维持正文段落，不把缓存 JSON 当作文本书籍打开。

## 验证

本次验证包含 27 本书的完整分页、分类后分页、未读书显示、缺封面、详情与更多菜单返回、迟到的简介更新、可读文件实际落盘，以及保留原缓存的错误处理。新增原生界面检查使用官方 KOReader 控件代码，覆盖 600×800 的 12 本网格和完整简介滚动。

最终运行结果与安装包校验记录单独保存在 `dist/verification-0.3.1.md`，界面预览为 `dist/compact-preview-0.3.1.png`。预览通过生产控件绘制，但字体、屏幕与图像设备边界使用桌面替身，不能当作 Kindle 截图。

本次已适配四源完成三轮共 12 次真实网站搜索、详情、目录、正文及实际 HTML 文件交接，全部通过。919 源合集本次 HTTP 200，官方 SQLite 驱动保存、重开比较和重复导入去重通过。这不代表全部 919 个书源或每本书均能阅读。

## 最短验收与边界

安装后确认书架每页最多 12 本、翻页能看全收藏；切换顶部分类，点书查看封面与简介。导入已适配四源后搜索“三国”（英文小说网使用“加”），选择书籍开始阅读，翻页并关闭、重新打开检查进度。

**尚未验证**：没有连接 Kindle，也没有本次设备报错堆栈。已复现并修正两个阅读错误，但不能声称穷尽该设备所有 STORAGE_ERROR 原因。真机存储、触摸、字体、墨水屏刷新、封面解码、网络和长时间阅读仍需设备验收。任意 JavaScript、登录及 WebView 仍不支持，部分书源和大目录仍存在上一版测试报告列出的限制。
