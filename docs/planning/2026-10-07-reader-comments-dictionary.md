# 阅读评论与词典修复临时规划

范围：在现有无感阅读、评论控制器和卡片界面中修复导航与错误标记，不引入依赖。

## 已核对的根因

- `reader_terms.lua` 从所有《书名号》猜测词典入口，没有官方蓝色可点击标记依据。
- 阅读菜单打开随文评论后直接列出所有读者，缺少按原文片段聚合的入口。
- 章末入口把加载状态及首条点赞数画在正文下方，违反只显示“章节讨论”的要求。
- 当前代码已隐藏未知点赞数；截图中的旧提示在本版代码不存在，设备版本待核对。

## 方案比较

1. 仅改文案：小，但不能修复原文与读者之间的导航关系。
2. 新建评论页面：重复现有卡片、分页、头像及请求生命周期，维护成本高。
3. 复用现有界面（采用）：原文列表进入对应读者，再进入全文及回复，保持返回位置；取消猜测词典入口，真实协议另行核对。

## 阶段与验收

1. 评论导航：修改 `weread_comments.lua`、`chapter_discussions.lua`，同一原文范围只显示一次入口，不同范围不合并；菜单先原文，正文下划线直接对应读者；返回保留范围和页码；失败/迟到回包不重开旧页面。
2. 展示：修改 `leko_reader.lua`，章末仅一个标签；章节讨论复用四张读者卡片，真实赞和回复数保留，未知值隐藏。
3. 词典：移除书名号推断；保留主动长按查询；先用真实回包判定查询失败原因，不假设登录失败，不猜测蓝色标记接口。
4. 交付：运行针对性回归、完整检查与官方 KOReader 兼容检查，独立审查后生成安装包，同步原交接目录。设备与 GitHub 交付以实际状态为准。
