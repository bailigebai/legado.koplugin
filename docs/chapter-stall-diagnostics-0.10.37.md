# 在线跨章卡顿取证（v0.10.37 开发包）

用户报告：在线阅读未整本缓存的书，约每 20 章偶发一次跨章卡顿；无感和 KOReader 原生模式均会遇到。当前没有同次设备日志，不能认定是哪一层耗时，也不能宣称卡顿已经修复。

## 本次加入的计时

阅读会话在等待更多目录和同步保存目录时分别记录 `catalog_wait`、`catalog_persist`。原有的正文获取、进度保存、读者准备和绘制阶段继续计时。超过阶段阈值的事件写入普通警告日志，以 `[LegadoTimingSlow]` 开头；快速事件只留在调试日志中。

日志字段为阶段、毫秒、阅读后端、切章序号、累计毫秒和当时目录章数。不会记录书名、站点网址、章节网址、正文、Cookie 或密钥。`attempt 0` 表示该计时不属于已经创建的切章事务；`chapters 0` 表示该阶段没有章数信息。一次卡顿可能出现数条慢事件，要结合时间先后看。

## 实机取证

1. 安装同一份 v0.10.37 开发包，在线阅读未整本缓存的书；发生卡顿时记下大致时间、书源名称、书名、当前章节、阅读模式，以及是自动翻到下一章还是从目录跳转。
2. 不必反复复现；出现一次后，复制 Kindle 上的 `koreader/crash.log`。保留同次日志的 `[LegadoTimingSlow]` 行和卡顿前后约一分钟的相关错误行。
3. 分享前可遮盖个人账号、Cookie 或其他插件的私密日志；不要删掉 `[LegadoTimingSlow]` 的阶段、毫秒、后端、序号与章数。

## 判断范围

- `catalog_wait` 慢：需要检查书源目录分页、网络返回及后台扫描状态。
- `catalog_persist` 慢：需要检查目录 JSON 写入与 SQLite `replaceChapters` 的实际耗时，再决定是否改成增量保存。
- `foreground_content` 慢：需要检查正文请求、预取命中与站点响应。
- `reader_ready`、`page_prepare`、`reader_validate` 或 `paint_drawn` 慢：需要检查相应阅读后端的构建、排版或屏幕提交。

这些字段用于缩小范围，不等于单条日志能证明最终根因。桌面模拟规格和打包检查不能替代 Kindle 实机计时。
